# API_CONTRACTS — Quot3

**This is a frozen contract. Edit in place to extend it; never silently diverge from it in code.**
If a phase needs a function, channel, or table not listed here: **add it to this doc first** (signature + owner module + test/fixture name), then implement to match. Never implement first and document later.

There are three layers of contract:
1. **Shared pure functions** (`src/shared/*`) — no I/O, no Electron, no DOM; Vitest-covered.
2. **IPC channels** (`src/main/ipc/*`) — renderer → main, Zod-validated, typed envelope.
3. **The bridge** (`window.quot3.*`, `src/preload/index.ts`) — the only door from the UI to the world; mirrors the IPC channels 1:1.

Types here are TypeScript-flavoured pseudocode; the real definitions live in `src/shared/types.ts` and must match.

## 0. Common types (`src/shared/types.ts`)


### `money.ts` (Phase 6)
| Export | Signature | Notes |
|---|---|---|
| `D` | `(v: Dec \| number \| null \| undefined) => Decimal` | decimal.js; `null/''` → 0 where documented; throws on non-numeric |
| `isNumericStr` | `(s: string) => boolean` | accepts `-`? `.`? digits; used by numeric cells |
| `round2` | `(d: Decimal) => Decimal` | ROUND_HALF_UP, 2 dp |
| `toDec` | `(d: Decimal) => Dec` | canonical string, trailing zeros trimmed to ≥ 2 dp for money, none for qty/rate via `fmtQty` |
| `fmtMoney` | `(d: Dec, opts?: {indian?: boolean; symbol?: boolean}) => string` | `₹1,07,500.00` |
| `fmtQty` | `(d: Dec) => string` | trims `.0` |
| `add/mul/sum` | decimal helpers | no JS-number math anywhere else |

**Phase 6 concrete shape:** `D(v)` parses strictly (blank/null → 0; throws on exponents, hex, NaN, Infinity, thousands commas) · `tryD(s) => Decimal | null` (non-throwing, for user text) · `isNumericStr` = complete cell value (`-`? digits, one optional `.`) · `round2`, `roundInt` (ROUND_HALF_UP) · `toDec` = canonical trimmed string (`"12.5"`, `-0`→`"0"`) · `toMoney` = 2-dp string (`"90.00"`, never `"-0.00"`) · `fmtMoney(v, {indian?, symbol?})` (default plain 2 dp; `₹1,07,500.00` with both) · `fmtQty` (trims; blank/invalid → `""`) · `add`/`mul`/`sum` return `Decimal` (convert with `toDec`/`toMoney`). Money values coming out of `calcRow`/`computeBill` are 2-dp strings.

### `calc/billTotals.ts` (Phase 6)
```ts
computeBill(format: FormatDef, rows: BillRow[], opts?: { roundOff?: boolean }) => {
  display: DisplayRow[];   // item rows, then footer rows in the owner's order, plus slNo per item row
  slNo: Record<Id, number | null>;
  itemsTotal: Dec; itemsGst: Dec; itemsAmount: Dec;
  adjustments: { rowId: Id; total: Dec }[]; adjustmentsTotal: Dec;
  grandTotal: Dec;         // items total (or amount in GST) + adjustments total (+ round-off line if enabled)
  counts: { itemRows: number; adjustmentRows: number; paperRows: number };   // paperRows = item + adjustment rows (D-C3)
  warnings: string[];
}
```
**Phase 6 decisions on `computeBill`:** `display` = non-adjustment rows in entry order (item/blank/partial), then the footer; adjustments move into the footer block. No adjustments and no round-off → one `grandTotal` row labelled `Total`; otherwise `itemsTotal` ("Items total") → adjustment rows → `adjustmentsTotal` → [`roundOff`] → `grandTotal` ("Final total"). Footer cell placement is driven by `format.footer`: `'total'` → Total column; `'total_gst_amount'` → the items-total/Total row fills total+gstAmt+amount, every other footer row (adjustments, round-off, final) uses the Amount column only. Round-off (opt-in) shows only when non-zero; extra field `roundOff: Dec`. Partial rows are displayed, never totalled; a nameless item is totalled and flagged. Warnings are `CODE:rowId`. Labels exported as `FOOTER_LABELS`.
`DisplayRow = { kind: 'item'|'blank'|'partial'|'adjustment'|'itemsTotal'|'adjustmentsTotal'|'grandTotal'|'roundOff'; rowId?: Id; slNo?: number; cells: Record<string, string>; }`

A row is blamed at most once per run; the 10th attempt makes it `failed` and it is left alone until `retryFailed`. `kick()` (called after every captured change, 250 ms delay, coalesced) does nothing while backing off; `notifyOnline()` clears the backoff and runs soon. Overlapping `runOnce()` calls share one run. **Phase 57 as built (conflicts and tombstones).** **Ordering** (unchanged, now exact): `incomingWins` = newer `updatedAt`, else higher `revision`, else greater branch id; equal never wins. A tombstone for an unknown bill is inserted. **Conflict = a local version loses a race.** When the incoming version wins and the local version differs in content (`shared/sync/conflict.ts` `sameContent`: party, format, extra columns, paper, date, delete flag, PO fields and every row cell; revision, times, totals cache and sync state are NOT content), it is a conflict if the local bill is `pending` (never sent), OR it was made here and the winner's revision is not higher (the winner cannot have seen it). Revision rows above the applied revision are removed (a lower number that wins through a later time would collide with the next local save) and the row for the applied revision is REPLACED (two branches reach the same number with different content); the lost local version therefore lives in the audit snapshot. **State:** `conflict` is not cleared by sending (`markSynced` keeps it) nor by a later pull; a new local save sets `pending` again; the owner can dismiss it: `sync:dismissConflict { billId }` -> `{ done }` (back to `pending` if something is unsent, else `synced`). `sync:conflicts {}` -> `ConflictInfo[]` (bills still in conflict, latest row each: `billId, poNumber, at, lost, loserRevision, loserUpdatedAt, winnerBranch, winnerRevision, winnerUpdatedAt, winnerDeleted`; no snapshot).
