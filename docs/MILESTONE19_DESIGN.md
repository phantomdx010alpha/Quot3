**Testing rule (owner's standing rule, repeated on purpose):** do NOT run the full test suite in any Milestone 19 phase except the final gate (Phase 204), and only if the owner agrees. Run the typecheck once plus only the files you wrote or changed plus those that could plausibly conflict (named per phase in `PHASES.md`). No desktop build, no dev server. ## 1. What the owner wants (firm decisions)

1. A **Games page** in the Windows app with many free, PLAYABLE games, searchable. The games come from **public GitHub repos with permissive licences, copied into the app, so we do not write the games ourselves** (the owner's words: "so we don't have to write code from scratch"). "Billions" was an exaggeration; a few dozen to about a hundred good games is the target.
2. **Chess** is included (play against the computer, and two players on one PC).
3. A new Dashboard tile whose visible name is exactly **"(?)"** and nothing else. Default behaviour [A]: it opens a RANDOM game (the owner has not said; fits the name). The Games page is reachable from the nav item.
4. **Desktop (Windows app) only. No phone PWA work at all.**
5. Everything works offline. No network call is ever made by or for a game.

## 3. Hard rules (binding for Phases 197–204)

1. **No API, no key, no network.** The main process makes no request for games and the renderer makes none. The production CSP strings for the app window are NOT loosened except for the single, narrow `frame-src` in rule 3.
2. **Vendored, read-only, licensed.** Each game lives under `resources/games/<gameId>/` (shipped through `extraResources`, like `resources/fonts`), exactly as upstream (no rewriting its code, only the minimum patches listed in `docs/THIRD_PARTY_GAMES.md`, each patch recorded as a unified diff), with the upstream LICENSE text kept in `resources/games/<gameId>/LICENSE`. `resources/games/manifest.json` lists every game: `id, title, tags[], description, source (repo URL), commit (SHA), licence (SPDX id), author, entry (relative html), players (1|2), touch (bool), added`. A pure schema + test rejects a manifest entry with a missing field, a non-allowed licence id, or an `entry` that is not inside its own folder.
3. **Local game host, one origin per game.** A privileged custom scheme `q3game` (registered before `app.ready`, `standard`, `secure`) served by the main process from the read-only games folder, with the host name = the game id (`q3game://<gameId>/index.html`), so each game has its own origin and its own `localStorage` (high scores survive restarts; games cannot read each other's data or the app's). The handler: resolves paths inside the game's folder only (no `..`, no absolute paths, no symlink escape: tested), serves read-only, returns a restrictive per-response `Content-Security-Policy` for the game frame (`default-src 'self' data: blob:; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' data: blob:; connect-src 'self'; frame-ancestors <app origin>`; no `unsafe-eval` [A]). The app window's CSP gains exactly one entry: `frame-src q3game:` (both the production and the dev CSP in `src/main/security.ts`, with `security.test.ts` updated to assert it and nothing else changed). The game runs in an `<iframe sandbox="allow-scripts allow-same-origin allow-pointer-lock allow-forms">` (no `allow-top-navigation`, no `allow-popups`, no `allow-modals`). A session `webRequest` filter additionally cancels any request from a game frame that is not `q3game:`, `data:` or `blob:` (belt and braces).
4. **Audit before vendoring (every game, no exception).** A script `tools/audit-games.mjs` (plus a test) scans each game folder and FAILS on: any `http://` / `https://` / `//cdn` reference to a remote script, style, font, image or media (a plain link in text or a comment is reported and reviewed), `fetch(`, `XMLHttpRequest`, `WebSocket`, `navigator.sendBeacon`, `eval(`, `new Function(`, `importScripts` of a remote URL, `document.cookie` writes, `window.open`, `location.href =` to another origin, analytics / ad / tracking snippets (gtag, analytics, adsbygoogle, mixpanel, sentry), obfuscated or minified-only code with no readable source [A], files larger than 25 MB, or an executable / binary other than images, audio, fonts, wasm, JSON. The audit result for each game is recorded in `docs/THIRD_PARTY_GAMES.md`. A game that fails is dropped or patched with a recorded patch.
5. **IP and trademark filter.** MIT covers the code, not the name or look of a game. Never ship a game that copies a known commercial game's name, characters or art (Mario, Pac-Man, Galaga, Tetris, Flappy Bird, Angry Birds, Pokemon, Zelda, Minecraft and the like) under that name. For a generic game that merely resembles one (a snake game, a falling-blocks game) use a neutral title ("Blocks", "Snake", "Ghost Maze"), keep no copied sprites or sounds, and list it in the log. The owner uses Quot3 personally today [A]; if it is ever SOLD, this filter becomes mandatory and Phase 204 re-checks it.
6. **Licence compliance.** MIT / BSD / ISC / Apache keep their notice: the Credits screen (Games page footer link and Settings > Games) lists every game: title, author, repo URL, licence id and commit, and opens the full LICENSE text inside the app. `docs/THIRD_PARTY_GAMES.md` is the master record; it is also bundled as `resources/games/THIRD_PARTY.txt`. CC-BY-SA art (if the chess set needs it) is credited the same way and kept separate from code.
7. **The games are not part of a bill.** They add no row to any bill, party or item table, no Supabase or sync change, no SQL under `supabase/sql`, no schema change, no migration. Per-PC state (favourites, last played, play counts) is the single setting `games.state` (JSON, small) in the existing settings store; high scores stay inside each game's own `localStorage` (not read, not exported by Quot3). Not synced, [A] included in the backup file as a plain setting.
8. **Keyboard first, never trapped.** The Games page is searchable and keyboard driven (Tab, arrows, Enter). The player screen has a top bar OUTSIDE the iframe: "Back to games", the game title, a Fullscreen toggle, and a Restart-game button (reloads the frame). Keys typed while the game has focus go to the game only (the app's hotkeys do not run), so the way out is: the Back button, or `Alt+Left` caught in the main process through `webContents` `before-input-event` so it works even when the frame has focus [A]. Esc is left to the game; when focus is on the page (not the frame) Esc follows the Phase 94 Dashboard-rooted model.
9. UI rules as everywhere: tokens only (no raw colours) for Quot3's own screens, Phosphor icons only (`GameController` for Games, `Shuffle` / `Question` for the tile if an icon is needed: the tile itself shows only text), no emoji in Quot3 UI, the Phase 92 selector rule, every control has an accessible name. Game content is the game's own look and is not restyled.
10. **Stockfish (optional, only with the owner's OK).** Default [A]: NOT shipped in the first pass; chess uses the MIT minimax AI (levels 1–4 by search depth). If the owner agrees to GPLv3 for that component (they use Quot3 personally today), Phase 201 adds the lite single-thread build as a Web Worker run through `q3game://`, as a separate, clearly labelled component with its full GPL text and corresponding-source offer on the Credits screen. **If Quot3 is ever sold or given to others, the owner must decide again first (legal advice recommended; this document is not legal advice).**
11. **Existing behaviour must not change** for bills, history, customers, items, print, image copy, sync, backup, the Dashboard's other tiles. New code goes in new files wherever possible; edits to shared registries (`routes.ts`, `navItems.ts`, `shortcuts.ts`, `live.ts`, `tileLayout.ts`, `settings.ts`, `TodayTiles.tsx`, `security.ts`, `window.ts`, `electron-builder.yml`) are small, additive and covered by their existing tests (updated, not deleted).
12. Docs-only changes need no version bump and no tag. Each code phase bumps the version in `package.json` and both spots at the top of `package-lock.json` (`GITHUB_UPDATE_PUSH.md` section 2) and hands back the changed-files zip, the full zip and the push steps with the real version. Real Windows behaviour (how each game plays, sound, keyboard, installer size) is never written as "verified" from the sandbox; it goes in Standing gaps.

## 4. The pieces

### 4.1 Pure core (`src/shared/games/`, Phase 197)
No DOM, no Electron, no network. `manifest.ts`: types and a strict validator for `manifest.json` (rule 2), `ALLOWED_LICENCES`, `GAME_TAGS` (puzzle, arcade, card, board, shooter, word, retro, two-player, chess, relaxing), `searchGames(list, query, filters)` (Fuse.js is already a dependency: name, tags and description; typo tolerant; empty query returns everything sorted), `sortGames` (favourites first, recently played, A-Z), `pickRandom(list, state, rng)` (for the tile: avoids the last played game when more than one exists, injectable rng for tests), `gamesState.ts` (`GamesState { favourites: string[]; lastPlayed: Record<string, string>; plays: Record<string, number> }`, parse / update / cap at 500 entries, unknown ids pruned), `gameUrl(id, entry)` (builds `q3game://<id>/<entry>` with strict id and path checks), `isSafeGamePath`.

### 4.2 Local game host (Phase 198)
`src/main/games/gameProtocol.ts` (scheme registration, handler, path safety, CSP header, network filter), `src/main/games/gameCatalog.ts` (reads `manifest.json` from the resources folder via `runtimePaths.ts`, validates it, returns the list; an invalid entry is skipped and counted, never crashes), IPC (`games:list`, `games:getState`, `games:setState`, `games:pickRandom`, `games:getCredits`, `games:getLicense` (by id, returns text), zod `.strict()` inputs, `wrapHandler`), the preload surface, `electron-builder.yml` `extraResources` (`resources/games` -> `games`), `security.ts` `frame-src q3game:`, the `Alt+Left` handler.

### 4.3 Vendored games (Phases 199–201)
Batches (each phase: copy, record, audit, patch minimum, add manifest entries, add one smoke test that loads the entry file text and checks the audit passes):
- **199** `skymoon173/mini-game-collection` (the 21 `games/*` folders that pass; not the legacy folders), `bushimashen/games`, `TomMalbran/games`, `gd4Ark/2048`, `mumuy/pacman` (renamed per rule 5 if needed).
- **200** `wangzifan396-wzf/mini-browser-games`: only grade S / A games that pass the audit and the IP filter (target 30–40, written in the log with the dropped ones and why), and the generic games from `davidzhanghui/awesome-mini-game`. Duplicates (several 2048s, several Snakes) are collapsed to the best one per type.
- **201** Chess: `chess.js` + `chessboard.js` + `zeyu2001/chess-ai` as "Chess" (play vs computer: White / Black / random side, 4 levels, undo, flip board, new game, two-player on one PC mode, move list), `kbjorklu/chess` as "Chess (classic)" if it adds anything; the piece-art licence resolved (rule 6); optional Stockfish lite (rule 10).
Target: roughly 60–100 games in all. Upstream names of files are kept; a game that cannot meet the audit is dropped, not rewritten.

### 4.4 Games page and Settings (Phase 202)
Route `/games` (`ROUTES.games`), nav item (`GameController`, "Games"), shortcut `nav.games` `Ctrl+6` [A] (must pass the conflict test in `shortcuts.test.ts`; pick a free key if taken), command-palette entry. Page: search box focused on arrival, tag chips, a card grid (title, tags, 1 or 2 players, favourite star, last played; virtualized if the list is long), "Favourites" and "Recently played" filters, "Random game" button. Player screen: top bar (rule 8) + the sandboxed frame filling the page; opening a game updates `lastPlayed` and `plays`. States: no games found, game failed to load (plain message + Back), manifest problems counted in Settings. Settings > Games (page id `games`): on / off switch (`games.enabled`, default on [A]; off hides the nav item, shortcut, palette entry, route and the tile), "Clear favourites and history", the number of games, the Credits screen link, a plain sentence "Games run on your PC only and never use the internet."

### 4.5 The "(?)" Dashboard tile (Phase 203)
`DASH_TILE_KEYS` gains `'games'`; `TILE_LABELS.games = '(?)'`; `DEFAULT_DASH_TILES.games = true` [A]; stored `dash.tiles` objects that lack the key read as the default (existing PCs keep their other tiles). The tile shows the text **(?)** and nothing else; a real button (`aria-label` "Random game" is allowed because the visible text stays "(?)"); click or Enter opens the Games player with `pickRandom`. `tileLayout.ts` today supports 1–6 tiles; seven must also have no orphan row: wide windows `[[4,4,4],[3,3,3,3]]`, narrow windows `[[6,6],[6,6],[4,4,4]]` [A]; `DASH_TILE_KEYS.length` becomes 7, the `Math.min` clamp, the doc comment and the tile-layout tests are updated. Hidden when `games.enabled` is off (the rest re-flow with the 1–6 rules) or when the catalogue is empty. Settings > Dashboard lists it as "(?)".
