## 1. Notification stacking (Phase 116)
Owner: each time a page is switched with Esc, many unrelated notifications stack up and are annoying. Screenshot: four identical "Image copied - 675 x 228 px - paste into WhatsApp" toasts. Code: `components/ui/Toast.tsx` keeps up to 5 toasts, 4 s each, global, never cleared on navigation, no de-duplication. Plan [A]: identical messages replace each other (one toast, timer restarts), all toasts clear on page change, at most 2 visible, routine confirmations (undo/redo notices, "saved", repeated copy confirmations) become a quiet status-line text instead of a toast. FIRST step: list every notice the Esc path can raise (owner has not yet given the texts) and record them in the phase log.

## 2. Items page: names invisible (Phase 117)
Owner screenshot (Items): Groups window blank except the first load, scroll thumb low; Spellings truncated ("JUPITER BELT ..."); pressing Down for more shows empty rows although the other two windows still show the selected data. Found by reading the code: Groups is virtualised with `@tanstack/react-virtual` inside `.q3-items__content` (rows absolutely positioned with `translateY`), Phase 115 already added a re-render workaround for the scroll element. Likely cause: the virtualiser measures a different element than the one that scrolls (not confirmed). Fix: one scroll element, measured after layout, rows beyond the first screen render; Spellings name column wide enough (flex / min width, full name in tooltip); Sales stats ignore zero/empty-rate lines (the owner's screenshot shows "rate 0 - 260" because a 0 line is counted and flagged "Low"). Test with 3 000+ groups and keyboard Down to the end.

## 3. Create always opens blank (Phase 118)
**Hard rule (owner):** clicking Create always opens a clear, formatted, empty bill. This supersedes the Phase 70 [A] "unsaved bill resumes with a New button". [A] Leaving Create with unsaved work still asks Save / Discard / Cancel (Esc guard); a crash-recovery draft is offered only at app start. Editing an existing bill from History/Items/View is a different route and is unaffected. Cause of "sometimes opens a pre-made bill": not yet diagnosed (reproduce first: which entry paths reuse the session: side rail, Ctrl+N, Esc-back, History-back).

## 4. Clipboard in the Create grid (Phase 119)
Owner: Ctrl+C / Ctrl+V still do not work on Create; with a range selected, pressing Ctrl alone makes focus go off and "nothing happens" before C is pressed; Ctrl+V does nothing; pasting tab-separated text must work. Code facts (read): `gridController.ts` registers `copy` / `cut` / `paste` listeners on the root and passes every keydown (including a bare Control key) through `navReduce`; copy uses `document.execCommand('copy')`; paste has a bridge fallback (`clipboard:readGrid`). Root cause unknown; never exercised in a real window. Plan: reproduce with a real-window e2e (select a range, Ctrl down, C, then paste TSV from Notepad/Excel), make modifier-only keys inert (no focus or selection change), make Ctrl+C / Ctrl+V / Ctrl+X work with a range, a cell and in Free mode, keep the existing clipboard rules. Top-priority bug.

## 5. Round-off not applied to grand totals (Phase 120)
Owner: "the automatic round-off to the closest number still doesn't happen in the grand totals". Code facts (read): the per-bill flag `roundOff` is set from `calc.roundOff` when a NEW bill is created (`Create.tsx`) and again at save (`billService`, `opts.roundOff?.()`), and totals use `getBillOptions`. Why it fails on the owner's PC is not found. Plan: reproduce for every path (new bill, bill opened from History, imported bill [0 by design], after Save, print, image, TSV), check the setting's actual stored value and the flag on the bill in the DB, fix the path(s), and add an end-to-end style test (create -> total shown -> save -> reopen). Owner to say which paths fail.

## 7. Delete row (Phase 122)
Owner: in Create, pressing Delete on a row deletes that row only, excluding the extra-column content for that row. [A] Interpretation: with the row selected (click the row number, or Shift+Space), Delete removes the item cells (name, qty, rate, amount) and the rows below move up; the extra-column cells stay on their row positions (extras are free cells; same rule as reordering). Delete on a single cell keeps its current meaning (clear the cell, D-K4). One undo step; units counts and marked segments are recomputed in display order; adjustment rows and totals are not row-deleted; empty rows after the last item are trimmed as today. Paper row counts update.

## 8. Row reordering (Phases 123–124)
Owner: rows can be rearranged as wanted, without compromising what is built; tell the drawbacks first. Drawbacks recorded: (a) extra columns are positional free cells; units counts and marked segments run by display order - decision [A]: items move, extras stay on their row positions (consistent with delete); (b) per-word formatting moves with the item cells; (c) one undo step per move; (d) sync / revision diff and History compare see order changes (`sameContent`/`diffBills` already compare rows by position and must treat a move as a change); (e) print / TSV / image follow the new order; (f) paste, Down-extends-tail-rows, smooth-arrow rules unchanged; (g) keyboard-first: Alt+Up / Alt+Down move the active row (to be confirmed by the shortcut-conflict test), mouse drag by a handle is optional and secondary; (h) no schema change (rows are already an ordered list); (i) perf: a move re-renders only the affected rows (render-count harness). Nothing completed needs renumbering.
